About Draft vs PickNet

Draft vs PickNet is a Magic: The Gathering draft simulator that runs entirely in your browser. You draft against seven bots driven by PickNet, a model trained on human drafts from 17Lands. Packs are opened from each set's MTG Arena collation. When the draft ends, a deck model trained on 17Lands game results builds your deck. The same tools work on sealed pools.

Run a copy on your own computer and you also get the Live tab. It follows your MTG Arena drafts as you make them, with PickNet's pick and WheelNet's wheel odds for the pack in hand. See Run it locally for how.

The code for this site is at github.com/zscore/mtg-draft-sim-site.

The research behind it

Each model has its own repository and write-up. The PDFs open on GitHub.

PickNet: what would a human pick?

An 8.4M-parameter transformer that predicts which card a human drafter takes from a pack. It reads the whole draft so far: every pack shown, every pick made, and what the other seven drafters took. One model covers every set on the site. In the paper's 17 sets, it agrees with the human pick on 70.8% of held-out picks. On the site it drives the bots, the "PickNet's view" percentages and the pick ratings.

  • PickNet: One Transformer for Human Draft Picks in Magic: The Gathering, Trained on 17 Sets (paper, PDF)
  • How PickNet Works (step-by-step architecture guide, PDF)
  • Code: zscore/picknet

WheelNet: will this card come back?

A pack you pass returns eight picks later. WheelNet predicts which of the cards you passed will still be in it, from the raw draft history, and cuts log loss by 8.6% against the usual per-card average (ALSA). The paper also asks whether reading an open lane pays. On the site, WheelNet gives the wheel odds on the Live tab.

  • Will It Wheel? Predicting Which Passed Cards Come Back in Magic: The Gathering Drafts, and Whether the Open Lane Pays (paper, PDF)
  • How WheelNet Works (step-by-step architecture guide, PDF)
  • Code: zscore/wheelnet

TableNet: one network for picks and wheels

PickNet and WheelNet combined: the all-sets pick model with a wheel head, trained on both tasks at once. This is work in progress and not on the site yet. The notes cover the design and what the October runs showed about where its wheel predictions fall short of the per-set WheelNets. TableNet lives in the wheelnet repository.

  • TableNet: One Network for Picks and Wheels (design note, PDF)
  • TableNet: Where the Wheel Gap Comes From (research note, PDF)
  • TableNet with a wheel history encoder (diagram, PDF)

Deck strength: how good is this deck?

How strong a drafted deck is, separately from who plays it, from 17Lands game data across 12 sets, along with what each card is worth and whether card synergy is real. The deck builder's "Build best deck" and its predicted win rates come from the game-level model in this work.

  • Skill-Adjusted Deck Strength from 17Lands Data (report, PDF)
  • Deck strength: overnight results (research note, PDF)
  • Transformers should join the blend, not replace it (literature review, PDF)
  • Code: zscore/mtg-deck-strength

mtg-data: the shared data

The data layer every model above uses. It downloads 17Lands' public draft, game and replay files, converts them to parquet, and holds the card encodings the models share.

  • Code: zscore/mtg-data
  • Data: 17Lands public datasets (please check their usage guidelines)

Updating everything

When 17Lands publishes new data, or a new set comes out, the models and the site's data are rebuilt in this order: data, then models, then the site. This takes a machine with about 30 GB free and a few hours of training. Most people don't need to do it. Running the site locally (Run it locally) only needs this repository.

0. Put the repositories side by side

The tools find each other by folder name, so clone them all into one folder:

mkdir mtg && cd mtg
git clone https://github.com/zscore/mtg-data.git
git clone https://github.com/zscore/picknet.git
git clone https://github.com/zscore/wheelnet.git
git clone https://github.com/zscore/mtg-deck-strength.git
git clone https://github.com/zscore/mtg-draft-sim-site.git

Each model repository has its own Python environment, with mtg-data installed into it:

cd picknet
python3 -m venv .venv && source .venv/bin/activate
pip install -e ../mtg-data -r requirements.txt

Do the same in wheelnet (it also needs -e ../picknet) and mtg-deck-strength.

1. Download the data (mtg-data)

From any of those environments, inside mtg-data:

python scripts/download.py            # every set (about 26 GB)
python scripts/download.py FRA        # or just the sets you name

This downloads 17Lands' files, converts them to parquet, and sanity-checks them. Everything goes in mtg-data/data/. Set MTG_DATA_DIR to keep it somewhere else; every repository and the site's tools read the same variable. To refresh a set with a newer 17Lands file, delete its cached raw and parquet files first.

2. Retrain PickNet (picknet)

The all-sets model is fine-tuned, not trained from scratch. Its card table only ever grows, so a new set's cards are appended:

python scripts/card_text_embeddings.py NEW   # rules-text embeddings for the new set's cards
python scripts/build_pick_shards.py NEW      # adds NEW to the card table and builds its shards
python scripts/train_picknet_all.py name=all_d256_new ... init=results/picknet_all/models/<latest>.pt

The "Adding a set" section of the PickNet README has the full training command and the checks to run first. Fine-tune on all sets, not just the new one, so the others don't drift.

3. Train a WheelNet for the set (wheelnet)

python scripts/build_dataset.py NEW    # wheel labels and features
python scripts/train_nn.py NEW         # the WheelNet transformer

4. Rebuild the site's data (mtg-draft-sim-site)

A new set first needs its pack collation in tools/collation.py. Then:

python tools/export_model.py [checkpoint.pt]        # PickNet -> model/picknet.onnx (picknet's environment)
python tools/build_data.py NEW                      # cards, Scryfall images, collation, mana facts -> data/NEW.json
../wheelnet/.venv/bin/python tools/export_wheelnet.py NEW   # WheelNet -> model/wheelnet_NEW.onnx
python tools/export_deck_model.py NEW               # deck model -> data/deck/NEW.json

The deck-model export still imports code from before the deck work moved to mtg-deck-strength. It needs updating to the new repository before it runs again. Until then, sets keep the deck models they have, and a new set gets the PickNet build only.

Check the exports against the originals before publishing:

python tools/make_fixture.py && node tools/verify_js.mjs   # the browser's PickNet vs PyTorch
node tools/check_wheelnet.mjs NEW                          # the browser's WheelNet inputs vs training
node tools/verify_deck.mjs NEW                             # the browser's deck model vs PyTorch
python tools/verify_packs.py NEW                           # generated packs vs real 17Lands packs

Then commit and push to master. GitHub Pages republishes the site within a minute or two.
